> 本文是 EraTrans 迁移基准清单，不代表功能已经迁移或通过运行验证。

> 旧版源码基准：Future-R/ErbParserForTranslate，master，SHA 623447acfb3063a18371b719811b9f4e2373fe03（2026-11-19 盘点）。
>
> EraTrans 当前基准：main，SHA 720227bd3f7f5777a899c8335796354e68b9a0a8。扫描器 PR #2（feature/dictionary-extraction）仍为 Open、未合并；CI run 44447597687 已成功。

## 1. 迁移验收原则

1. 目标是保留旧程序所有有实际用途的非破坏性功能，而不是只迁移“提取字典”。
2. 解析结果必须尽量与旧程序一致：输入文件范围、编码、解析规则、过滤条件、key、original、translation、stage、context、条目顺序和异常处理都属于兼容范围。
3. 原程序对游戏目录、用户源文件或输入字典的原地修改/删除行为不迁移。相关功能若仍有价值，改为输出到独立目录或副本，不覆盖、不删除、不重命名原始输入。
4. 旧行为差异或疑似 bug 先登记并建立回归样例。迁移和修复分开；未经明确批准，不静默“优化”旧逻辑。
5. 代码级审查不等于行为兼容验证。必须使用相同输入和配置运行旧程序与新程序，比较输出 JSON 结构及内容；没有真实样本的项目标记为“待验证”。

## 3. 解析范围及数据格式约定

### 3.1 文件范围

- CSV/**/*.csv：普通 CSV 提取。
- ERB/**/*.erb、ERB/**/*.erh：同目录存在同名 ERB 时跳过独立 ERH，由 ERB 解析器自动把 ERH 内容拼到 ERB 前面；只有 ERH 时会单独解析。
- ERB/**/*.erd：既解析 ERD 内容，也从文件名生成 CSV/ERD字典.json。
- resources/**/*.csv：资源 CSV，有单独的取值及翻译替换逻辑。
- XML/**/*.xml：指定 XML 结构提取。
- ERB/**/*.xml：旧版主提取流程只有在根 XML 目录存在时才将这些 XML 加入队列；这一条件需要用旧程序样本确认，不能由扫描器悄悄改变。

### 3.2 旧 PT 条目 key / 字段语义

| 来源 | 普通提取 key | 字段特征 |
|---|---|---|
| ERB 文本 | 文本 + 相对路径去扩展名 + 5 位序号 | 有 translation、stage；配置允许时写 context |
| ERB 变量 | 变量 + 相对路径去扩展名 + 5 位序号 | 有 translation、stage；配置允许时写 context；受屏蔽变量输出设置影响 |
| 普通 CSV | 相对路径去扩展名 + 5 位序号 | 有 translation、stage；没有 context |
| resources CSV | 相对路径去扩展名 + 5 位序号 | 普通输出没有 stage；对照输出使用 图像 前缀 |
| XML | 相对路径（保留 .xml） + 5 位序号 | 有 translation、stage；没有 context |
| ERD 文件名表 | 文件名 + 3 位序号 | 输出在 CSV/ERD字典.json，original 是 ERD 文件名（不含扩展名） |

ERB 的 JSON 条目顺序是变量项在前、文本项在后。过滤、去重会改变列表及序号，因此不能只检查最终条目数量。普通 CSV/RES/XML 与 ERB 的 key 规则不同，EraTrans 现有“只认文本前缀”的 key 规则不能承担完整旧 key 分类。

### 3.3 解析器行为必须原样保留的部分

- CSV：先截断分号注释，再截断第一个左括号后的内容；按逗号切分；忽略第一列、空项和纯整数（默认）；保留旧 TrimStart 行为。它不是 RFC CSV 解析器。
- resources CSV：类似注释截断，但取第一列 Trim；旧方法的 banNumber 参数并未实际过滤数字。
- ERB：保留 skip 标记、注释优先级、花括号跨行合并、PRINT/SPLIT 特例、函数和变量声明、CALL/CALLF、赋值/表达式拆解、变量/文本分类、上下文收集、过滤和去重等整条解析流程。不能用简化正则替代。
- [SKIPSTART] / [SKIPEND]：忽略行首分号注释的标记；有效 START 到有效 END 之间的内容被跳过；没有有效 END 时丢弃后续剩余内容。
- XML：只提取代码中指定节点/属性，不是通用 XML 文本提取。范围包括 defname 相关字段、triggeredskill、randomCharaTalentES、enemy_data、command、GMAPDATA、title、titleBonus 等。
- 替换：普通脚本按已翻译条目构造正则替换计划，按 original 长度降序；resources 使用独立行替换方法。旧的 LockReplace/Aho-Corasick 路径已标记 Obsolete，不应误作当前默认路径。

## 6. 已登记的兼容风险 / 需要基准样本确认的点

1. **ERH 自身拼接风险**：ERBParser.ParseFile 对任意输入都会检查同名 .ERH 并拼接。如果单独传入 .ERH，改变扩展名后仍可能指向自身，导致内容重复。目录批量提取会跳过有同名 ERB 的 ERH，但单文件入口仍可能触发此行为。
2. **XML 扫描条件不一致**：旧 ReadFile 只有在根 XML 目录存在时，才把 ERB/**/*.xml 加入 XML 队列；当前 PR #2 扫描器不依赖 XML 目录是否存在，会始终扫描 ERB 下 XML。是否修正旧行为必须单独决定并记录。
3. **版本更新不处理 XML**：旧 VersionUpdate 的处理任务只有 CSV、ERB/ERH、resources、ERD，没有 XML。不能仅因主提取支持 XML 就推断版本更新也支持 XML。
4. **版本更新对旧条目的保留行为**：MergeEntries 按新解析条目遍历，只加入新版本中仍存在的旧条目和新条目；源码没有把新版本中已消失的旧条目追加回输出。这与 README 中“过时词条不会删除，而是隐藏”的描述存在疑点，需要用旧程序输出确认。
5. **ERD 输出路径**：PZJson.输出ERD字典使用相对工作目录的硬编码 CSV\ERD字典.json，不显式使用 ReadFile 的 appPath；不同启动工作目录可能产生不同结果。
6. **资源 CSV 字段差异**：普通 RES 输出缺少 stage 字段；不要自动补齐，否则会改变旧 JSON。
7. **XML key 差异**：常规 XML key 保留 .xml 扩展名；合并模式还有变量前缀和路径处理差异。
8. **配置与过滤**：需要对 forceFilter 两套正则、hideEngText、hideVarOutput、mergeSameText、mergeString、writeContext、fileEncoding 逐项做测试。
9. **编码探测**：旧版本 UtfUnknown 识别结果和 Shift-JIS 特殊映射必须用含日文、UTF-8 BOM、无 BOM、UTF-16 的样本验证。
10. **文件比较**：A/B 比较先做长度与原始字节比较，之后忽略所有 CR 字节再比较；这不是按文本编码解码后的换行比较。

## 7. 迁移分阶段建议

1. 建立黄金样本和格式契约：准备 ERB/ERH、CSV、RES、ERD、XML、传统 ERA、PT/MTool JSON 样本及对应旧配置；保留旧程序输出作为 golden files。
2. 迁移纯解析核心：先迁移 Configs、Tools 中纯字符串/正则规则、CSV/RES/XML/ERB/ExpressionParser；不带目录清理、文件删除或游戏文件写回。
3. 迁移 PT 数据转换功能：PT/MTool、传统 ERA、查重填充、context/乱码清理；所有任务采用只读输入 + 独立输出。
4. 迁移目录工作流：初次提取、对照提取、版本更新、单文件提取、A/B/C 差异提取；逐项与 golden files 比对。
5. 迁移游戏副本处理：编码转换、字典翻译、ERD 重命名、自动修正；只对副本运行并验证原目录哈希不变。
6. WPF 接入：核心行为通过测试后，再连接任务进度、路径选择、设置和输出浏览。不要把解析逻辑放入 UI 事件处理器。
